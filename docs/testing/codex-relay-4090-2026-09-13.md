# 4090 relay verification — 2026-09-13

User requirement: use SSH host 4090 as a relay, test a stable service for
phone/desktop shared Codex sessions without installing a phone VPN.

Installed on the current Mac: isolated authenticated Codex app-server on
127.0.0.1:17329 and supervised reverse SSH to 4090's 127.0.0.1:18329.
Both are login launch agents, not system boot daemons. Codex version 0.153.4.
Existing website, FRP configuration and native desktop process were not changed.

Executed against real 4090, with a temporary SSH local forward on port 17330:

- `scripts/verify-codex-relay.cjs`: missing token and wrong token HTTP 401;
  valid token accepted, both direct and via relay.
- 20 sequential read-only `thread/loaded/list` RPCs: direct median 0.27 ms,
  P95 0.33 ms; via relay median 59.63 ms, P95 142.07 ms. This route crosses
  Mac→4090→Mac; it is not a phone-cellular benchmark or throughput estimate.
- `scripts/verify-codex-shared-session.cjs`: real model, same thread on two
  protocol clients, output received by both, reconnect restores history,
  disconnect during generation preserves execution and identical turn IDs.
  No prompt resent. Thread: `01a099f6-f04b-7f72-ad2e-eabe290773fa`.
- Killed only the test launch agent's SSH process (PID 11238); launchd spawned
  PID 11439 and the remote loopback listener returned in 1.1 seconds.
  This verifies process-exit supervision, not a prolonged network outage.

Repeatable execution instructions: [deployment README](../../deploy/codex-relay/README.md).

Not implemented/verified: public website WSS routing and account pairing,
native desktop UI sharing this app-server, real Android phone access,
lost-acknowledgement send deduplication, prolonged outage/backoff, cold boot,
backend crash mid-generation, soak/load tests and log rotation. 待真机验证。

official app-server probes are test clients, not a new app business protocol.
