1. **Codex / DSH 沙箱环境**：已有记录显示 PRoot 下描述符执行返回 182、bubblewrap 读取 overflowuid 被拒绝、Landlock 不可用等问题。普通 shell 可执行、错误详情能展示，都不能证明沙箱修复。见 [运行能力记录](../testing/current-runtime-capabilities-20260909.md) 和 [Codex 复现](../testing/codex-terminal-exit-20260909.md)。
2. **完整候选收敛**：集成目录还有大量未提交代码/测试/证据；外部候选尚未审查。必须明确最终 diff，不能把所有目录直接覆盖打包。
3. **性能承诺**：长列表懒加载不等于完成大历史真机帧时间验收；没有证据证明“每次等待 10 秒”整体消除，暂不列为完成项。
4. **新能力边界**：不把 session/resume 宣称为执行暂停恢复，不宣称新增消息固定、固定条数滚动窗口或长期记忆重写。

## 收尾顺序与发布条件

1. 在此集成分支逐模块提交现有工作树修改，先确认来源和测试，保留他人未完成修改；按上表审查外部分支，纳入、替代或延后都记录结论。
2. 保持单一上下文预算/摘要实现和单一 ACP 生命周期；核对上游版本、许可证以及 checkpoint 持久化语义。不同阶段的补丁不能叠加成两套机制。
3. 对最终代码运行现有 `scripts/test-agent-runtime.sh`、上下文场景入口及排版回归；WebChat 按项目规则执行 typecheck/build，不自行增加浏览器验收。
4. 核对最新版本编号后设置 0.6.2.3，生成最终 APK，记录提交与 APK SHA，覆盖安装保留数据。较早的 0.6.2.2 安装记录不替代这一步。
5. 同一候选上执行聊天切换、长任务与压缩、文件/图片/HTML、终端停止/恢复、权限返回、定时任务和重启场景；物理设备上记录设备、版本、操作和结果。
6. 沙箱仍不可用时，在版本已知问题中明确说明；不能标成已支持并通过，也不能静默降为不受限执行。
7. 审核通过后再推送 PR/正式发布；当前本文不是“0.6.2.3 已发布”的声明。
