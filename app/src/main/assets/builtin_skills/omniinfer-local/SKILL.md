# 使用本地模型服务

这是按需技能。只在本次安装、启动或验收任务中访问服务；任务结束后停止探测，不添加常驻提示词或轮询。

## 默认：主 App 内的官方推理组件

通过已有 GUI 能力进入模型 Provider 设置，点击小入口“使用本地模型服务”，在原生页面点击“下载并启动”。当前实验版支持 Android 11+ ARM64，下载固定版本约 27 MB 的组件与约 610 MB 的 Qwen3 0.6B Q8_0 模型，并验证 SHA-256；重复启动校验并复用文件。组件由官方 Maven `io.github.omnimind-ai:omniinfer:0.2.4` 打包，和模型都不内置主 APK。官方服务在主 App 进程内运行，不需要安装另一个宿主或 SDK/NDK。

等待页面的实际加载结果。下载进度不是推理进度，“服务已启动”也不是 Agent 验收通过。若 9099 被旧宿主占用，先通过旧宿主的“停止服务”释放端口，不能将旧服务的响应当作新组件验证。下载、校验或加载失败时报告页面具体错误，不自动回退云端、旧 APK 或源码构建。

旧 App 没有此原生页面时，报告需更新到支持按需组件的版本，不假装新入口已经可用。

## 验证和 Provider

使用现有终端中的 Python 执行一次：

```sh
python3 <scriptsDir>/probe.py --port 9099
```

该脚本读取 `/health`、`/v1/models`，发送真实推理请求，要求非空回复。Provider 使用 `http://127.0.0.1:9099/v1`、Chat Completions、空 API Key；模型 ID 必须来自本次 `/v1/models`，不要猜测或更改无关 Provider。按用户要求通过已有 Provider 配置入口选择本地模型。

切回正式对话后，用当前 ACP 会话和已有工具完成用户的实际任务。记录真实模型输出、工具调用与实际产物；仅 API 探测通过不能宣称 Agent 已可用。若没有输出，保留当前 turn 并排查，不能重复提交任务、伪造工具结果或切到云端。模型本身不支持可靠工具调用时明确报告限制。

验证返回主对话、重复启动、停止再启动和主 App 重启后复用下载文件。停止使用时点“停止服务”。服务不自动在 App 冷启动时加载；下次需要时由用户或此次 Agent 任务打开入口启动。

## 明确要求源码构建或旧独立宿主

只有用户明确要求时读取 [旧宿主与源码构建流程](references/legacy-host.md)，其中 `phone.py build` 保留从头拉取并构建能力，`phone.py prepare` 是旧独立 APK，并非此按需组件。旧宿主在部分真机上会被厂商冻结，不能把它当作本方案的默认替代。
