# 首页更新入口与聊天键盘性能改进

首页可用更新按钮已独立放在搜索入口左侧。聊天页减少了聚焦、输入框展开和键盘高度变化引起的重复构建，保留现有输入法配置、编辑器、历史滚动和 ACP 生命周期。

同一台 PJD110 / Android 16 实测：在手机当前使用的 **Flutter JIT 调试模式**下，键盘首次抬升的中位数减少约 23–28 ms，完整展开减少约 21–24 ms；触摸后 800 ms 内累计 UI 帧耗时减少约 21%。Profile AOT 同样减少 UI 工作量，但键盘展开时间基本不变。不能将本次结果解释为系统输入法动画被缩短，或所有设备的卡顿都已消失。

## 定位与修改

- `ChatPage` 原来订阅整个 `MediaQuery`，聚焦和输入框逐帧高度回调还会触发整页 `setState`。现在沿用原有键盘几何计算器，只通知位置和留白消费者，标题栏、编辑器、工作区、消息列表主体保留。
- 消息列表与加载/空态共用 `ChatMessageViewport`，键盘只更新 Padding 和空态对齐。消息内容及 Sliver delegate 不随每个键盘高度样本重建。
- 纯聊天原先每次构建都执行 `where().toList()`，丢失 Observable 消息源及时间线缓存。现在在现有结构版本缓存失效时过滤工具卡，保留推理、答案和行级流式更新。
- 气泡和欢迎区改为订阅所需的 MediaQuery 属性，避免无关的键盘变化触发重建。
- 实际点击回归证明输入框在首帧就请求键盘；展开不产生新的 `TextInput.setClient` 或 `updateConfig`。未对输入框配置或系统动画做猜测性修改。

## 同机 JIT 前后结果

每个版本、每个场景保留 10 次，先丢弃 2 次预热。下表时间单位均为 ms；延迟为每次测量的中位数，帧 P95 为每次测量 P95 的中位数。

| 指标 | 空白新对话：修改前 → 修改后 | 200 条历史：修改前 → 修改后 |
| --- | ---: | ---: |
| 收到触摸 → 聚焦 | 5.530 → 5.514 | 5.214 → 4.851 |
| 收到触摸 → 键盘首次非零高度 | 127.802 → 99.511 | 112.325 → 89.582 |
| 收到触摸 → 首次到达最终高度 | 406.721 → 382.423 | 396.773 → 375.868 |
| 触摸后 800 ms 内 UI 帧 P95 | 17.451 → 11.395 | 17.793 → 12.253 |
| 同窗口累计 UI 帧耗时 | 315.266 → 250.259 | 290.061 → 228.842 |

随后装回同一旧 JIT APK，每场景再测 5 次：UI 帧 P95 分别为 20.197 / 19.969 ms；累计 UI 帧耗时为 329.091 / 302.708 ms；首次键盘抬升为 129.499 / 132.303 ms。旧版复测没有复现新版较低的工作量和延迟，但不据这些小样本声称已排除全部系统调度噪声。

## 同机 Profile AOT 对照

样本数、数据和操作相同；同样进行旧版每场景 5 次交叉复测。

| 指标 | 空白新对话：修改前 → 修改后 | 200 条历史：修改前 → 修改后 |
| --- | ---: | ---: |
| 键盘首次非零高度 | 78.582 → 81.473 | 79.844 → 81.129 |
| 首次到达最终高度 | 362.089 → 364.544 | 362.394 → 364.189 |
| 触摸后 800 ms 内 UI 帧 P95 | 3.657 → 2.870 | 5.136 → 3.505 |
| 同窗口累计 UI 帧耗时 | 148.350 → 110.711 | 157.096 → 110.116 |

累计 UI 帧耗时分别减少 25.37% / 29.91%。旧版复测为 147.771 / 154.099 ms，支持应用侧重复工作的减少。AOT 键盘完整展开仍约 360 ms，没有明显加速证据。

800 ms 是预先固定的触摸响应观察窗口，包含输入框展开、键盘、欢迎区移动及尾帧，**不是只包含键盘运动的窗口**。优化后便宜尾帧的数量也变化，因此不能把这一窗口的 P95 降幅等同于键盘运动期峰值降幅。作为敏感性检查，仅取首个非零 inset 到最终高度，AOT UI P95 中位数分别是 3.616 → 3.784 ms、5.136 → 4.994 ms，并无稳定的大幅下降。累计帧耗时也不是 CPU 时间、实际 FPS 或用户等待时间；不同帧阶段不能相加当作墙钟时间。

## 环境与复现边界

- 同一设备、百度 OPPO 输入法、深色主题；屏幕覆盖分辨率 1080×2376，480 dpi，显示报告约 120 Hz。没有因此假定每帧实际都达到 120 Hz。
- 电池温度 30.4–30.8°C，各次读取 Thermal Status 均为 0。没有更改手机输入法、系统动画倍率或刷新率设置。
- 两种 Flutter 模式分别比较；原生层均为 debug、未 R8。Profile AOT 不能直接当作完整 production release。正式安装包经只读 APK 文件名检查确认含 `kernel_blob.bin`，因此另做 JIT 对照。
- 原始 Android pointer timestamp 也保存，但未核对其与 Dart 时钟的基准；上述延迟从 Flutter **收到** PointerDown 开始，不能代表硬件触摸到屏幕呈现的全部延迟。
- 所有测量都是预热后的键盘。新会话准备时会自动聚焦，再收起后测量，不能称作输入法首次冷启动。
- 使用真实 `main_standard`、`ChatPage`、`ChatInputArea` 和系统 IME。历史通过真实保存及分页服务装载完整 200 条合成消息，未用近似界面替代。
- baseline 为 `9844da4c9fb27774911fb9b7f776895c8142b897`；after 为本次工作区源码快照。两者探针一致，测量后曾确认快照与当时工作区的 Dart 文件哈希一致；后续并行修改见下文。
- 全过程使用独立包 `cn.com.omnimind.bot.keyboardperf`，覆盖安装只保留其合成数据；未读取正式聊天数据库、未发送模型消息。测试结束已卸载独立包并删除本次 VM 转发和私有连接文件。

## 验证与证据

604 项相关 Flutter 测试通过，覆盖新/历史对话点击、键盘逐帧可见性、编辑器及组合输入保留、消息内容/Sliver delegate 稳定、纯聊天过滤和流式更新、键盘几何及首页入口。定向分析无新增 warning/error；正常 `main_standard.dart` 入口的 `assembleDevelopStandardDebug` 构建成功。

正常 APK 位于 `app/build/outputs/apk/developStandard/debug/app-develop-standard-debug.apk`，application ID 为 `cn.com.omnimind.bot`，不含性能探针。本轮未覆盖手机正式安装，本轮改动未提交或推送。
