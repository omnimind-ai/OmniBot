# Provider 模型选择：实时查询验证

## 用户行为

- 普通聊天和 Agent 输入栏均提供独立的服务商／模型入口，ACP 会话参数仍使用原入口。
- 选择器立即显示；读取已配置 Provider 后，各自并行请求模型目录。失败可以单独重试。
- 弹层销毁后释放查询结果；重新打开重新请求。请求的晚到结果不更新已关闭弹层。
- Flutter 不再持久化远端模型目录，也不以旧目录作为失败回退。
- 服务商配置、手工模型和用户已选绑定仍持久保存。目录缺少模型不再清除会话覆盖配置。
- Agent 配置页复用同一实时选择器。Provider 设置页显示配置后拉取目录，并保留原刷新按钮。

## 验证（2026-09-06）

- 116 个相关 Flutter 测试通过，覆盖模型服务、实时选择器、Provider／场景／Agent 设置页、ACP 参数和输入栏。
- 新回归覆盖：不持久化远端目录、旧目录不会复活、手填配置保留；一家请求挂起时仍可选择另一家；单独重试；重开重新请求；关闭后的晚到响应。
- `:app:assembleDevelopStandardDebug -Ptarget=lib/main_standard.dart` 构建成功。
- APK 安装到 `emulator-5556` 成功。Agent 输入栏能直接打开多个 Provider 的列表；此次设备目录请求失败时显示逐 Provider 重试，原选中模型 GLM-5.1 保持。
