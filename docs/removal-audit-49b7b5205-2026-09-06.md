## 为什么不机械恢复其他旧行为

该提交同时删除功能、修改实现并修复数据/协议问题。195 个文件不是 195 个独立误删功能。

| 旧代码类别 | 审查判断 |
| --- | --- |
| materializeRecord、prepareEntryForStorage 的截断/占位修复 | 旧方案可避免读取崩溃，却会用摘要、空 payload 或占位内容替换大记录；不恢复这种有损行为，改用无损分块读取。 |
| Provider 拒绝请求后换模型、去图片、改 thinking 的 fallback | 可能改变用户选定的模型及内容。保留当前 Provider 权威配置和单一传输 owner；不将其作为本次已确认误删恢复。 |
| overflow、length、缺少技能工具时自行拼接“继续”并再次请求 | 与正常容量维护不同，可能改变正在执行的任务；保留现有 ACP prompt/取消/终态修复，不恢复这些重放/合成用户消息路径。 |
| 工具正文、文件、终端输出、附件和 UI 展示的固定裁剪 | 恢复固定截断会重新丢失用户要求的原文。当前实际崩溃由底层读取分块解决，不靠截短用户内容规避。 |
| 内存加载去重占位、记忆条数限制、自动写入失败学习 | 是否自动省略/写入记忆属于另一个行为决策；本次不改变长期记忆 API 和数据，不把旧策略一概视为恢复目标。 |
| 本地按工具名分批并发、技能完成合同、集中运行时上限 | 不作为本次三项已证实故障的修复依赖；不重新引入额外调度或隐含上限。保留现有官方配置/工具入口。 |
| ACP 身份、会话恢复、历史投影、配置转换器拆分，以及 Flutter/WebChat 生命周期调整 | 属于后续修复和职责整理，按用户选择保留。 |

## 后续边界澄清：安全保护保留，主动运行限制不恢复

用户明确要求：不要删除安全保护，只删除主动运行限制。此前“不机械恢复”不等于所有剩余删除项已证明无害。

本轮沿用 SubagentDispatcher → AgentOrchestrator → AgentToolCatalog.validateArguments：

- 通用子 Agent 保留父 Harness 已提供的能力，没有新增轮数、Token、时长、递归深度或结果长度上限。
- 规划器不执行工具；探索者只获得现有读取/观察工具，并在参数校验处拒绝 browser_use 的 click/type/execute_js 等操作；记忆管理员保留记忆写入及文件读取。权限是角色的行为契约，不是任务预算。
- 工具列表与真正执行使用同一权限判断。按现有工具名称和来源类型匹配，不将同名 plugin/MCP 工具当成本地读取工具；错误仍由原 Orchestrator 配对回传。
- 子 Agent 传递父环境 permissionRequester，复用同一 ACP 审批入口。原高权限 handler 在该入口缺失时会拒绝操作；本次恢复审批可用性，不声称此前能绕过审批。
- 保留父路由器的资源所有权和协程取消，不添加第二个生命周期。

断流源码复核：onClosed 缺少终止标记会报错，onFailure 走现有异常出口，finally 取消 EventSource；可选 idle watchdog 未删除。默认不启用固定空闲超时，避免把长时间正常思考当成失联。半开连接且没有任何网络错误通知的情况仍不能凭这些检查证明能自动识别，本次没有新增定时重试或硬性时长限制。
