### Fix

- `LocalAcpRuntime` forwards official available-command notifications after the
  existing session initialization mutex releases, using the runtime-owned scope.
  The SDK notification callback returns immediately so it can read the
  `session/new` response; directly waiting in that callback blocked the receive
  loop in an intermediate candidate and was corrected before final acceptance.
  Undispatched coroutine start queues notifications on that mutex in arrival
  order. No timer, retry, persistent catalog cache or second Agent lifecycle.
- `AgentRuntimeManager` permits turnless command metadata to establish its
  session only when the source runtime owns it and the durable Conversation
  binding still points to that exact session. Ordinary messages, arbitrary turn
  IDs, unowned sessions and superseded bindings do not gain admission. Flutter
  uses the existing reducer and advertised-command dispatcher unchanged.
